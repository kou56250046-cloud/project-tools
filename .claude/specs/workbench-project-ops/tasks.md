# 案件ワークベンチ 案件の操作 — タスク

## T1 取り消しの段とリセット（store）
- 触るファイル: `src/ui/store.js` `test/project-ops.test.mjs`
- やること: undoById を段の配列に、undo・undoTo・canUndo・history()、resetProject。書き出しより前に戻ったときは revision だけ消す
- **完了条件:** テストで、25 回の変更の後に取り消せるのは 20 段、undoTo(i) で i 番目以降が消えて一度に戻る、案件を切り替えて戻ると段が残る、リセットで項目が型の質問だけになり案件名・設定が残り、token が変わり、取り消しで元に戻る。段の表示の種類（設定・ベースライン・リセット・取込）が正しい。500 項目の台帳の JSON の長さ ×20 が 20MB 未満

## T2 合言葉の変更（store）
- 触るファイル: `src/ui/store.js`
- 触るファイル（追加）: `test/passphrase.test.mjs`（localStorage の偽物を使う）
- やること: changePassphrase（保存の鎖に入れる・2 つのキーの書き戻し・開けない退避があれば止める）、persist が鍵を実行時に読む
- **完了条件:** テストで、(1) 違う今の合言葉では失敗し vault が変わらない (2) 変えた後は新しい合言葉で開け、古い合言葉では開けない。退避も新しい合言葉で開ける (3) 偽の localStorage で recovery の書き込みを失敗させると、vault と recovery が元の文字列のままで ok:false (4) 変更中に呼ばれた persist が、変更後の鍵で書く (5) 開けない退避があると変更が止まる。ブラウザでも (2) を再読み込みで確かめる
