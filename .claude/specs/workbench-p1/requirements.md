# 案件ワークベンチ P1（土台と往復） — 要件

ロードマップ: `~/.claude/plans/claude-code-pc-pc-gemini-notebooklm-pc-h-imperative-newell.md`

## 背景

- 利用者は SIer の PM/SE 1名。自宅PCでは Claude Code が使えるが、会社PCでは Gemini（Workspace版）・NotebookLM・ブラウザしか使えない
- 案件の情報（関係者・要望・制約・決定・課題・質問）が議事録・メール・資料に散らばり、「誰がいつ言ったか」「何が未確定か」を追うのに時間がかかる
- Gemini は文章を整理できるが、毎回の出力の形がばらつき、過去の内容と突き合わせて管理する場所がない
- そこで、案件データを含まないHTMLを自宅で作り、会社PCで「HTMLが指示文を作る → Gemini が差分JSONを返す → HTMLで確認して取り込む」という往復で案件台帳を育てる

## 用語

| 用語 | 意味 |
|---|---|
| 台帳 | 1案件の全情報を持つ JSON。ID でつながった項目の集まり |
| 項目 | 台帳の1要素。種別は 関係者・システム・要望・制約・要件・決定・課題・質問 |
| 関係 | 関係者・システムどうしのつながり（例: 発注、利用、連携） |
| 差分 | Gemini が返す台帳への変更の束。追加・更新・関係追加・案件情報の更新からなる |
| 確度 | 事実 / 推測 / 確認済み の3段階 |
| 指示文 | HTMLが生成し、ユーザーが Gemini に貼る文章 |

## 受入条件

### 台帳
- [ ] AC-01 台帳は 8 種別の項目（関係者・システム・要望・制約・要件・決定・課題・質問）と関係を持てる。全項目が ID・題名・確度・出典（0件以上）・リンク（0件以上）を持つ。出典は種類・参照先に加えて、日付と発言者（関係者 ID）を持てる
- [ ] AC-02 ID は種別ごとの接頭辞と連番（例: `RQ-001`）。差分の取込時に HTML が採番し、既存 ID と重複しない
- [ ] AC-03 「新規案件」を押し、案件名を入れて「業務システム新規」の型を選ぶと、標準のヒヤリング質問（15件以上）が入った台帳ができる。型を使わない空の台帳も作れる。今の台帳があるときは、置き換える前に確認を出す。未書き出しの変更があれば、確認の文にそのことを含める

### 指示文の生成
- [ ] AC-04 指示文の画面で目的（初期作成 / 議事録取込 / 資料からの追加 / 立場別レビュー 5種（エンジニア / PL / PM / 利用者 / 運用者） / 自由指示 / NotebookLM用の要点整理）を選ぶと、指示文が生成されコピーできる
- [ ] AC-05 NotebookLM用を除く9種の指示文には、差分JSONの形式と例・使える種別と値の一覧・今の台帳の項目一覧（ID・種別・題名・状態）・案件の概要と revision が入り、末尾に資料を貼る位置が示される
- [ ] AC-06 NotebookLM用の指示文は JSON を求めない。出力の形として「種別ごとの見出し（関係者 / 要望 / 制約 / 決定 / 課題 / 未確定の点）の下に、1行1件で内容・発言者・日付・出典の資料名を書く」ことを指示文に含める。この出力は「資料からの追加」の指示文の資料欄に貼って Gemini に渡す（この流れを指示文の画面に案内として表示する）

### 差分の取込
- [ ] AC-07 取込画面に Gemini の返答をそのまま貼ると、```json の囲み・前後の説明文があっても JSON 部分を取り出して読める
- [ ] AC-08 取り出した差分は1件ずつカードで表示される。更新は「変更前 → 変更後」、追加は内容全体を表示する
- [ ] AC-09 各カードは採用/却下を選べる（既定は採用）。「適用」を押すと採用分だけが台帳に入り、却下分は入らない
- [ ] AC-10 形式の誤り（必須項目の欠け・使えない種別や値・日付の形式・存在しない ID の参照や更新）は、どの操作の何が悪いかを日本語で示す。誤りのある操作は「却下」に固定され、採用できない。正しい操作は、誤りのある操作があっても適用できる。JSONとして読めないとき、または採用できる操作が0件のときは「適用」を押せず、台帳は変わらない
- [ ] AC-11 誤りがあるとき、誤りの一覧を含む「Gemini への修正依頼文」をコピーできる
- [ ] AC-12 差分の中で新規項目どうしを仮ID（`new:1` など）で参照でき、適用時に本 ID に置き換わる。参照先の追加が却下（誤りによる却下を含む）されたときの扱いは design.md の「参照フィールド」表に従い、そのカードに警告を出す
- [ ] AC-13 直前の1回の適用（詳細パネルでの変更を含む）を取り消せる。取り消しの情報はメモリにだけ持ち、再読み込みすると取り消せなくなる
- [ ] AC-13b 決定の追加で supersedes（置き換える決定）が指定されたとき、置き換えられた決定の状態は適用時に自動で superseded になる

### 画面
- [ ] AC-14 概要: 案件名・顧客・目的・期間・ゴール、種別ごとの件数、健康診断の上位5件（次にやること）を表示する
- [ ] AC-15 関係図: 関係者とシステムを、立場（顧客 / 自社 / 協力会社 / システム）の列に分けて SVG で描き、関係を線とラベルで描く。ノードを押すと、つながるノードと線以外が薄くなり、詳細パネルにそのノードを参照する項目（design.md の参照フィールドのいずれかでこのノードを指す項目）が出る
- [ ] AC-16 一覧: 全種別の項目を表で出し、種別・確度・状態・優先度・文字列で絞り込める。行を押すと詳細パネルが開く
- [ ] AC-17 詳細パネル: 全項目と出典（日付・発言者を含む）を表示し、この項目を参照している項目（逆参照。参照フィールドのすべてが対象）も表示する。参照先の ID を押すとその項目に移る
- [ ] AC-18 詳細パネルで「確認済みにする」と状態の変更ができる。この変更も取り消しの対象になる
- [ ] AC-19 決定ログ: 決定を日付の新しい順に並べ、理由・検討した他の案・決めた人・置き換えた決定を表示する

### 健康診断
- [ ] AC-20 次を検出して重要度（高・中・低）つきで一覧にし、押すとその項目に移る。並び順は 重要度 → 期限（早い順、無いものは後）→ ID。AC-14 の上位5件もこの順の先頭5件
  - 存在しない ID への参照（高）。参照フィールドのすべてが対象。取込では弾くため、主にファイルの読み込みで起こる
  - 期限を過ぎた未完了の課題・質問（高）
  - 担当（課題は owner、質問は askTo）または期限のない未完了の課題・質問（中）
  - 出典のない項目（中）。出典の種類が template のものは出典ありとみなす
  - 優先度 Must で確度が推測の要件・要望（中）
  - 推測のまま、updatedAt から7日以上たった項目（低）。質問は対象外（質問は内容の確かさを問わないため）
  - どの要件の links からも参照されていない要望（低）

### 保存と配布
- [ ] AC-21 台帳は変更のたびに localStorage（キー `anken-workbench:v1:ledger`）へ自動保存され、再読み込みしても戻る。保存に失敗したら画面に警告を出す
- [ ] AC-22 台帳を JSON ファイルで書き出せる。ファイル選択またはドラッグ&ドロップで読み込める。読み込むと今の台帳を置き換える前に確認を出す。JSONとして読めない・`type` が ledger でない・`validateLedger` の形の検査に通らないときは読み込まず、理由を表示する。存在しない ID への参照だけは受け入れ、健康診断で示す
- [ ] AC-23 最後の書き出しより後に変更があるとき、画面上部に「未書き出しの変更あり」を表示する。書き出した revision を localStorage（キー `anken-workbench:v1:exportedRevision`）に持ち、再読み込み後も表示が正しい。ファイルから読み込んだ直後は書き出し済みとみなす
- [ ] AC-24 HTML は1ファイルで、ダブルクリック（file://）で全機能が動く
- [ ] AC-25 CSP により外部への通信（fetch・画像・スクリプト・フォームの送信）がすべて禁止されている。ブラウザのネットワーク記録に、HTML 以外の要求が出ない（favicon の自動取得も出ない）
- [ ] AC-26 GitHub Pages で開いたとき「HTMLをダウンロード」ボタンで本体を保存できる

## 非目標

- ヒヤリングの循環・ボール管理・非機能要求グレードの点検・スコープ管理（P2）
- WBS・ガント・EVM・変更管理・定例会資料・週報（P3）
- データ設計・画面定義・見積（P4）、テストの対応表・複数案件の横断（P5）
- 台帳を同時に複数持つこと。1度に扱える台帳は1つ
- 項目をフォームで自由に編集すること。編集は差分の取込で行う（例外は AC-18 の確認済み・状態だけ）
- 項目と関係の削除、関係（ラベル・両端）の更新。誤った項目は状態（rejected / dropped / inactive / retired など）で無効にする。誤った関係は P1 では消せない（不要になったら P2 以降で `unrelate` を検討）
- 関係図のドラッグでの配置変更・力学レイアウト
- 2回以上前の適用の取り消し、変更履歴の閲覧
- Gemini API との直接連携、サーバー、Apps Script
- Excel/TSV・印刷・PDF への出力
- スマホ向けの画面調整（会社PCのブラウザ幅 1280px 以上を想定）
- 項目数が 500 件を超える台帳での速度
- 古いブラウザ対応（Chrome / Edge の最新版のみ）

## 制約

- 依存ゼロ（npm パッケージを使わない）。ビルドは Node 標準モジュールだけ
- 生成物は `index.html` 1ファイル。file:// で動き、実行時に通信しない
- 外部由来の文字列（台帳・差分）は `textContent` でのみ描画し、`innerHTML` に渡さない
- 案件データ（実案件の台帳）はリポジトリに入れない。サンプルはダミーのみ
- 公開先は GitHub Pages。公開の実行前にユーザーの確認を取る
- 個人情報: 関係者の氏名・所属は台帳に入れてよい（2026-11-25 ユーザー承認）。親規約の例外。データは会社PCのブラウザと書き出したファイルにだけ置き、リポジトリには入れない
- 会社PCで「GitHub の URL を開く」「.html をダウンロードする」「ダブルクリックで開く」は社内ルール上できる（2026-11-25 ユーザー確認）
- static-zero テンプレとの違い: ホスティングは GitHub Pages での「配布」だけに使う（実行時の通信はしない）。図は台帳が実行時に変わるため、生成時の静的 SVG ではなく実行時に SVG を描く
