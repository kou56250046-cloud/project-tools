- ユーザーの依頼（2026-11-26）: 「ダッシュボードデザインにグラフも入れてほしい」
- 今の概要画面は、案件情報・種別ごとの件数・次にやること（健康診断の上位 5 件）だけで、グラフが無い。gemini-kit のダッシュボードは、KPI のカードと横積み棒・折れ線で状況を一目で見せている
- ヒヤリングの回答:
  - 入れるもの: KPI 4 枚と要件の状態・ボールの状況・進捗の S カーブ・確度と期限の分布（全部）
  - 部品: dashboard スキルの dash.js を写す（gemini-kit と同じ部品）

## 受入条件

### 部品
- [ ] AC-01 dashboard スキルの `dash.js` と `dash.css`（`~/.claude/skills/dashboard/assets/`）をワークベンチに写して使う。写した元と日付をファイルの頭に書く
- [ ] AC-02 写した dash.css の色は、ワークベンチの :root の変数を指すように直す（P6a の「:root の外に #fff 以外の直書きの色を書かない」を守る。test/ui-colors.test.mjs は dash.css も対象にする）
- [ ] AC-03 CSP・依存ゼロ・file:// を保つ（dash.js は innerHTML を使わず、style は JS から設定するだけなので、そのまま使える。CSV のダウンロードは blob: の URL を持つ a 要素で、移動ではなくダウンロードなので CSP の指令に当たらない）

### 概要画面の並び
- [ ] AC-04 概要画面を上から次の順にする
  1. 案件情報（今のまま）
  2. 始め方の案内（項目が 10 件未満のときだけ。今と同じ条件）
  3. KPI 4 枚
  4. 要件の状態 ／ ボールの状況（横に 2 つ）
  5. 進捗の S カーブ（EVM の対象の作業があるときだけ）
  6. 確度の内訳 ／ 期限の分布（横に 2 つ）
  7. 次にやること（今のまま）
  8. 種別ごとの件数（今のまま。下に移す。説明用の表示でも出す）
- [ ] AC-05 各グラフにタイトル・単位・時点（今日の日付）・出典（「台帳 rev N」）を出す。グラフの下に、数値を読める代わりの表（dash.js の機能）を出す

### KPI 4 枚
- [ ] AC-06 次の 4 枚を出す。比べる相手（compare）は design.md のとおり
  1. 顧客待ち: 顧客が持つボールの件数と、いちばん長い待ち日数
  2. 期限切れ: 課題・質問・作業の期限切れの件数
  3. 要件の合意率: 取り下げを除いた要件のうち、合意の割合
  4. SPI（作業が無いときは「—」と「WBS を作ると出ます」）
- [ ] AC-07 KPI を押すと、関係する画面（顧客待ち → 課題と質問（絞り込みはしない）、期限切れ → 健康診断、合意率 → 一覧で要件、SPI → 進捗）を開く

### グラフ
- [ ] AC-08 要件の状態: 分類（機能・非機能の 6 大項目・非機能で大項目なし）ごとに、合意 / 案 / 取り下げ の件数の横積み棒。案の多い順
- [ ] AC-09 ボールの状況: 待ち先（顧客・自社・協力会社・未定）ごとに、待ち日数（設定の日数 N で区切る: N 日以内 / N 日超 / 2N 日超）/ まだ聞いていない / 日数不明 の件数の横積み棒
- [ ] AC-10 進捗の S カーブ: PV・EV・AC の折れ線（週ごと・人日の累計）。進捗画面と同じ値（computeEvm）
- [ ] AC-11 確度の内訳: 要望・要件・制約ごとに、事実 / 推測 / 確認済み / 未設定 の件数（この順）の横積み棒（取り下げ・不採用・解消を除く）
- [ ] AC-12 期限の分布: 期限切れ / 今週 / 来週 / それ以降 の件数の縦の積み棒（課題・質問・作業を系列にする）。対象は健康診断の期限切れと同じ決め方（未完了・期限あり・子を持つ作業を除く）

### 説明用の表示・台帳が無いとき
- [ ] AC-13 説明用の表示では、社内のみの項目を除いた台帳で数え、KPI の「顧客待ち」「期限切れ」、ボールの状況、確度の内訳を出さない。S カーブの AC は出さない（進捗画面と同じ）
- [ ] AC-14 台帳が無いときは今のようこそ画面のまま。合計が 0 件のグラフは「まだありません」と出す（dash.js の空の表示）。KPI の値が出ないときは「—」と理由の一言を出す（NaN を出さない）

### テスト
- [ ] AC-15 集計は DOM に触れない `src/core/dashboard.js` に置き、テストで値を確かめる（サンプル台帳と、端の場合: 作業なし・期限なし・取り下げのみ）

## 非目標
- 過去との比較の推移（スパークライン・前週比）。台帳は項目ごとの過去の状態を持たない（作業の進捗だけ記録がある）。比べる相手は目標値・ベースラインにする
- 概要以外の画面（進捗・健康診断など）のグラフを dash.js に置き換えること。今の S カーブ・ガント・ER は今のまま
- グラフの項目を押して絞り込むこと（KPI を押して画面を開くだけ）
- 複数案件の横断画面のグラフ
- dash.js の中身の改造（色の変数の対応と、写した元の記録だけ）
- 印刷用の整形
- 選んだ 5 つ以外のグラフ（テストの合格率・変更の件数・FP など）
- KPI の目標値（0 件・100%・1.00）を設定で変えられるようにすること
- KPI を押したときに、開いた画面を絞り込んだ状態にすること

## 制約
- P1〜P6a の制約をすべて引き継ぐ（依存ゼロ・file://・通信なし・CSP をハッシュで・innerHTML を使わない・属性に style を書かない）
- dash.js は ES module ではないので、ビルドで「写した部品」として JS の先頭に入れる（トップレベルの名前の衝突の検査の対象外にする代わりに、dash.js が作るのは `Dash` だけであることをテストで確かめる）
