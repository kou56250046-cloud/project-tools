# 案件ワークベンチ P4（設計と見積） — 要件

前提: P3（`.claude/specs/workbench-p3/`）が済んでいる。

## 背景

- 要件が固まった後のデータ設計・画面と連携の定義を、Excel で別に作っていて台帳と切れている
- テーブル定義書・DDL・CRUD 表は、決まった手順で作れるのに手作業で書き写している
- マスタの元データは、取り込む前に重複・必須漏れ・コード体系の崩れを点検したいが、毎回目で見ている
- 見積の根拠が WBS の積み上げだけで、規模からの見積と突き合わせられない

## 受入条件

### データ設計
- [ ] AC-01 種別「テーブル」（EN）を足す。物理名・論理名（題名）・説明・区分（自システム / 外部参照）・マスタの印・列の一覧を持つ。列は物理名・論理名・型・長さ・主キー・必須・外部キー（テーブル ID と列の物理名）・コードの形（正規表現）・説明を持つ
- [ ] AC-02 テーブルの物理名・列の物理名の重複、存在しない外部キーの参照先、主キーの無いテーブルを、取込の検証で誤りにする（主キーなしは警告）
- [ ] AC-03 データ設計画面で、ER 図（テーブルの箱に列を並べ、外部キーを線で結ぶ。自動で配置）を出す
- [ ] AC-04 テーブルを選ぶと、テーブル定義（列の表）を出す
- [ ] AC-05 DDL（CREATE TABLE・主キー・外部キー・NOT NULL・列と表のコメント）を、方言（PostgreSQL / SQL Server / Oracle）を選んで出し、コピーできる。外部キーの参照順に並べ、循環するときは ALTER TABLE で後から足す
- [ ] AC-06 名前の規則の点検を出す: 物理名が英小文字・数字・下線だけか（設定で大文字に切り替え可）、予約語との衝突（方言ごとの主な予約語）、30 文字を超える名前（Oracle を選んだとき）

### 画面・連携・CRUD
- [ ] AC-07 種別「画面」（SC）・「連携」（IF）・「バッチ」（BT）を足す
  - 画面: 区分（入力 / 照会 / 帳票）・項目の一覧（名前・型・必須・元のテーブルと列）・CRUD（テーブル ID と C/R/U/D）
  - 連携: 相手のシステム・向き（受信 / 送信）・方式（ファイル / API / DB / その他）・頻度・項目の一覧・CRUD
  - バッチ: 実行の契機・頻度・CRUD
- [ ] AC-08 CRUD 画面で、機能（画面・連携・バッチ）×テーブルの表を出す。どの機能からも作成（C）されないテーブル、どの機能からも参照されないテーブルを印で示す
- [ ] AC-09 健康診断に次を足す: どの要件からも links で参照されていないテーブル・画面・連携・バッチ（低）、どの作業からも links で参照されていない合意済みの要件（低）、作成されないテーブル（自システム区分のみ、中）

### 見積
- [ ] AC-10 見積画面で、ファンクションポイントの概算（NESMA 概算法: 自システムのテーブル 35、外部参照のテーブル 15、入力 4、出力 5、照会 4 を件数に掛ける）を出す。画面の区分・連携の向き・バッチから機能の種類を決める（下の設計）
- [ ] AC-11 生産性（人日 / FP）を入れると、見積の工数を出し、WBS の見積合計（BAC）と並べて差と比率を出す。生産性は台帳の設定に保存する
- [ ] AC-12 差が ±30% を超えるとき、健康診断に「中」として出す（生産性が入っているときだけ）

### マスタの点検
- [ ] AC-13 マスタ点検画面で、マスタの印のあるテーブルを選び、CSV / TSV を貼るかファイルを選ぶ（ファイルの文字コードは UTF-8 / Shift_JIS から選ぶ。既定は自動判定: UTF-8 として読めなければ Shift_JIS）と、列の定義と突き合わせて次を出す: 見出しと列の対応、主キーの重複、必須の空欄、型と長さの違反、コードの形の違反、外部キーの参照先に無い値（参照先のテーブルの元データも貼られているときだけ）
- [ ] AC-14 点検の結果は、違反の種類ごとの件数と、行番号つきの一覧で出す。元データは台帳にもブラウザの保存にも残さない（画面を離れると消える）

### 配列の項目の更新
- [ ] AC-16 列・項目・CRUD の配列は、更新すると丸ごと置き換わる。取込のカードで、更新によって消える列・項目・CRUD の要素を名前つきで警告する

### 指示文
- [ ] AC-15 指示文の目的「データ設計」（要件・決定からテーブルと列を作らせる。テーブルを更新するときは列を全部返すよう指示する）と「画面・連携の洗い出し」（要件から画面・連携・バッチと CRUD を作らせる）を足す

## 非目標

- ER 図のドラッグでの配置変更・手での配置の保存
- 正規化の自動判定・インデックス設計・パーティション
- DDL の ALTER（差分のマイグレーション）生成。毎回 CREATE 全体を出す
- 画面のレイアウト（画面イメージ）の作成
- IFPUG の詳細法（DET / RET / FTR を数える複雑度の判定）。NESMA 概算法だけ
- マスタの元データの保存・修正・書き出し（点検だけ）
- 10,000 行を超えるマスタの点検の速度
- Excel ファイル（xlsx）の直接の読み込み（CSV で保存して使う）。UTF-8・Shift_JIS 以外の文字コード
- 方言3つ以外（MySQL など）の DDL

## 制約

- P1〜P3 の制約をすべて引き継ぐ
- 版 2 のまま種別と項目を足す
- マスタの元データは顧客の実データになりうるため、メモリ上で点検するだけで保存しない
