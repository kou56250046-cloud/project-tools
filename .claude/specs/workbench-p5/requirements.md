# 案件ワークベンチ P5（テストと横断） — 要件

前提: P4（`.claude/specs/workbench-p4/`）が済んでいる。

## 背景

- 要件がどの設計で実現され、どのテストで確かめられたかの対応（トレーサビリティ）を、品質報告や監査のたびに手で作っている
- テストの観点（境界値・異常系・権限）の洗い出しが人によってばらつく
- 複数の案件を兼務すると、案件ごとに台帳を開き直さないと「自分の作業」と「返事待ち」が見えない
- 新しい案件の立ち上げで使える型が「業務システム新規」の1種類しか無い

## 受入条件

### テストとトレーサビリティ
- [ ] AC-01 種別「テスト」（TS）を足す。工程（単体 / 結合 / 総合 / 受入）・観点（正常 / 境界値 / 異常系 / 権限 / 性能 / その他）・手順・期待結果・状態（作成中 / 準備完了 / 合格 / 不合格 / 保留）・実施日を持つ。links で要件・画面・連携・バッチ・テーブルにつなぐ
- [ ] AC-02 トレーサビリティ画面で、要件（取り下げ以外）ごとに、つながる要望・設計の項目（画面・連携・バッチ・テーブル）・テスト（状態ごとの件数）と判定（テストなし / 未実施あり / 不合格あり / すべて合格）を表で出す。判定と工程で絞り込める
- [ ] AC-03 テスト画面で、テストを工程・観点・状態で絞り込める一覧と、工程ごとの合格率を出す。その場で状態と実施日を変えられる（この2項目に限る）
- [ ] AC-04 健康診断に次を足す: 合意済みの要件でテストが無い（中）、不合格のテスト（高）
- [ ] AC-05 指示文の目的「テスト観点の生成」を足す。対象（要件か画面、複数可）を選ぶと、その詳細（画面の項目・必須・型、関連する制約・非機能要件）を入れ、観点ごとのテストを返させる

### 複数の案件と横断
- [ ] AC-06 ブラウザの中に複数の台帳を持てる。上部の案件名から切り替える。新規作成は新しい案件として追加する。読み込みは、同じ案件名の案件があれば「その案件を置き換える / 別の案件として足す」を選ぶ確認を出し（置き換えるときは未書き出しの変更の有無も出す）、無ければ追加する。案件を「ブラウザから外す」ことができる（確認つき。書き出していなければその旨も出す）
- [ ] AC-07 合言葉は全案件で1つ。保存は全案件をまとめて暗号化する
- [ ] AC-08 P4 までの1案件の保存（暗号化済み）と、P1 の平文の保存のどちらを開いても、その台帳1件を持つ複数案件の形に自動で移す。案件のうち1件だけが読めないときは、その案件だけを退避して残りは開く
- [ ] AC-09 未書き出しの印と取り消しは案件ごとに持つ。取り消しは今開いている案件の直前の1回だけ
- [ ] AC-10 案件ごとに「自分」（関係者 ID）を設定できる
- [ ] AC-11 横断画面で、全案件について次を1画面に出す: 自分が担当の未完了の作業のうち期限切れか 14 日以内に終わる予定のもの、自分がボールを持つ（自分が担当・質問先の）未完了の課題・質問、顧客待ちが設定日数以上の課題・質問、案件ごとの健康診断の高の件数と SPI。項目を押すとその案件に切り替えて詳細を開く

### 案件の型
- [ ] AC-12 案件の型に「基幹システム刷新」と「パッケージ導入」を足す。それぞれ標準のヒヤリング質問を 20 件以上持ち、非機能の 6 大項目すべてに 1 件以上の質問がある
- [ ] AC-13 既存の型「業務システム新規」にも、非機能の 6 大項目すべてに 1 件以上の質問があるようにする

## 非目標

- テストの実行環境・自動テストとの連携・不具合管理（バグ票）
- 信頼度成長曲線などの品質グラフ
- 案件をまたぐ項目の参照（ID は案件の中だけで有効）
- 案件ごとに違う合言葉
- 案件名以外での同一の案件の判定（案件名が同じなら同じ案件とみなす）
- 説明用の表示中の横断画面（説明用の表示中は横断画面と案件の切り替えの一覧を出さない）
- 全案件をまとめた1ファイルの書き出し（書き出しは案件ごと）
- 横断画面での編集（表示と移動だけ）
- 案件の型の自作・編集の画面（型は `starter.js` で増やす）

## 制約

- P1〜P4 の制約をすべて引き継ぐ
- 複数案件の保存の形を変えても、P4 までの保存が読めること（AC-08）。読めないときは退避の仕組みで元のデータを残す
- localStorage の容量（ブラウザで約 5MB）を超えそうなときに気づけること（保存の大きさを設定画面に出し、4MB を超えたら警告）
