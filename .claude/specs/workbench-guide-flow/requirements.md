# 案件ワークベンチ 使い方を gemini-kit のような流れ図にする — 要件

## 背景
- ユーザーの依頼（2026-11-26）: 「使い方を gemini-kit のようなフロー図にしてほしい」
- 今の使い方は「最初の 10 分」「Gemini との往復」「案件の進め方」がカードと箇条書きで分かれている。全体の流れ・繰り返す部分・どこで行うか（Gemini / NotebookLM / このツール / 顧客）が一目でわからない
- gemini-kit の使い方（`~/projects/bunsekiya-manage/gemini-kit/src/js/guide.js`）の作り:
  - 全体の 1 周期の図: 箱と矢印。各箱に「済 / 今ここ / これから」と使う場所。押すとその段の説明へ
  - 段ごとのカード: 入れるもの → 使う場所 → 出るもの → 次に持っていく先、手順、関連ボタン、次の段へ
  - 1 回の会議の前後でやること（前日・当日・翌日）

## 受入条件

### 全体の流れの図
- [ ] AC-01 使い方の 2 章を「全体の流れ」にし、ワークベンチの 1 周期を SVG の流れ図で描く。段は design.md の FLOW_STEPS（準備 → 資料の下ごしらえ → 初期作成 → 取込 → 点検 → ヒヤリング準備 → 会議 → 議事録の取込 →（繰り返し）、要件が固まったら → 要件の合意 → 計画 → 設計・見積 → テスト、と文書づくり）
- [ ] AC-02 繰り返す部分（取込 → 点検 → ヒヤリング準備 → 会議 → 議事録の取込 → 取込）を、点線の枠と「↻ 会議 1 回ごとに回す」で囲む。戻りの線は破線
- [ ] AC-03 各箱に段の名前と使う場所（Gemini / NotebookLM / このツール / 顧客）を書く。使う場所の凡例を図の上に出す
- [ ] AC-04 案件を開いているときは、各箱に進み具合（✓ 済 / ● 今ここ / ○ これから / ↻ 繰り返し / ― 任意）を出す。判定の規則は design.md の stepStatus。「今ここ」の箱は太枠・薄い強調の地。initial が済で baseline が無いときは、どの箱も ● にならず、繰り返しの枠が太線になり「今は繰り返しの部分です」と出る。全段が済のときは「すべての段に手が付いています」と出る
- [ ] AC-05 台帳が無いとき・ロック中・説明用の表示のときは進み具合を出さず、「案件を開くと進み具合が出ます」と書く（ロック中でも図と説明は見られる）
- [ ] AC-06 箱はボタンとして働く。押す（または Tab で選んで Enter / Space）と、その段のカードへ移り、カードの見出しにフォーカスが移る。Tab で回る順は流れの順。キーボードで選んでいる箱は金の太枠で見える

## 非目標
- 画面の幅が狭いとき（760px 未満）の縦の流れ図。ワークベンチは 1280px 以上が前提
- 図をドラッグして並べ替えること・図の拡大縮小
- 「良い出力と悪い出力」「NotebookLM の手順」「Excel を NotebookLM に入れる流れ」「案件フォルダの決まり」など gemini-kit の使い方にある他の章の移植（P6 以降、変換や文書づくりを移すときに足す）
- 進み具合を保存すること・手で「済」にすること（台帳から毎回判定する）
- 他の画面（概要など）に流れ図を出すこと
- 使い方の文章を Gemini 向けの指示文と共通にすること
- ほかの画面から使い方の特定の段へ直接飛ぶリンク
- 毎朝と会議の前後の作業に、画面を開くボタンを付けること（段のカードにある）

## 制約
- P1〜P6a の制約をすべて引き継ぐ（依存ゼロ・file://・通信なし・CSP・innerHTML を使わない・属性に style を書かない）
- 図は実行時に SVG を DOM で組む（`s()` を使う）。色は CSS の変数（P6a の配色）をクラスで当てる。SVG の属性に色を直書きしない
- 段・矢印・会議の前後の定義は `src/core/guide-text.js` に置く（文章の唯一の置き場所）。判定は DOM に触れない `src/core/guide-flow.js`
