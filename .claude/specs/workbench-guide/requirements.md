# 案件ワークベンチ 使い方タブ — 要件

## 背景
- P1〜P5 で画面が 25 に増え、どこで何をするか・どの順に使うかが画面だけでは分かりにくい
- 説明は README にあるが、会社PCでは HTML だけを持ち込むので README は手元に無い
- Gemini・NotebookLM との往復（指示文 → 貼る → 取込）は、このツール独特の使い方で、最初に迷いやすい

## 受入条件
- [ ] AC-01 上段の分類の右端に「使い方」があり、押すと使い方の画面が開く。台帳が無いとき（初回）と、説明用の表示中も開ける
- [ ] AC-02 使い方の画面は、左の目次と右の本文の2段。目次を押すとその章へ移る。章は次の7つ
  1. はじめに（このツールで何ができるか・データの扱い）
  2. 最初の 10 分（合言葉 → 案件を作る → 初期作成 → 取込、の4手順）
  3. Gemini・NotebookLM との往復（指示文 → Gemini → 取込 の流れ図と、うまくいかないとき）
  4. 案件の進め方（立ち上げ → 要件定義 → 計画 → 設計 → テスト の段階ごとに、使う画面と指示文）
  5. 画面ごとの説明（分類ごとに、各画面の「何ができるか」「いつ使うか」）
  6. よくある困りごと（開いて読む形の質問と答え。10 件以上）
  7. 用語（ボール・ベースライン・EVM・FP など 10 語以上）
- [ ] AC-03 「最初の 10 分」と「往復」は、番号つきの手順のカードと矢印で、流れが一目で分かる図にする（文字だけの段落にしない）
- [ ] AC-04 4章・5章の各画面に「この画面を開く」ボタンがあり、押すとその画面へ移る。4章の各指示文には「この指示文を開く」ボタンがあり、指示文画面をその目的を選んだ状態で開く。押せるかどうかは画面のタブと同じ判定（`app.canOpen`）で決める
  - 台帳が無いとき: 押せるのは「設定」と「使い方」だけ。ほかは押せず、理由（「先に設定で案件を作るか読み込んでください」）を出す
  - 説明用の表示中: 道具・健康診断・横断は押せない
- [ ] AC-05 入口
  - 初回のようこそ画面に「使い方を見る」ボタン
  - 合言葉を入れて開く画面・合言葉を決めて暗号化する画面（ロック画面。locked / legacy）に「使い方を見る」ボタン。ロック中でも使い方の画面だけは開け、使い方の画面の上に「合言葉の画面に戻る」ボタンが出る。ロック中は上段の分類は出さない
  - 案件を作る途中で出る「合言葉を決める」ダイアログには入口を置かない（作成の流れを途切れさせないため。ダイアログの説明文はそのまま）
- [ ] AC-06 画面の一覧（id・分類・名前）は `src/core/screens.js` の表を正とし、app.js も使い方もここから作る。画面ごとの説明・章の文章・困りごと・用語は `src/core/guide-text.js` の表に持つ。4章の指示文は prompts.js の `PURPOSES` の id で指し、名前は PURPOSES から引く
- [ ] AC-07 説明用の表示中は、5章・4章から、説明用の表示で隠れる画面（道具・健康診断・横断）と指示文の説明を除く（顧客に社内向けの画面の存在を見せないため）

## 非目標
- 画面ごとの「?」ボタンや吹き出しでの説明（使い方タブだけ）
- 操作をなぞるチュートリアル・アニメーション・動画・画像
- 使い方の中の検索、スクロールに合わせて目次の強調を追う機能
- 使い方の文章の編集・追加の画面
- README の内容の自動の取り込み（README は開発者向けとして残す）
- 「合言葉を決める」ダイアログへの入口（AC-05）

## 制約
- P1〜P5 の制約をすべて引き継ぐ（依存ゼロ・外部通信なし・textContent のみ・style 属性なし）
- 案件のデータを使い方の画面に出さない（説明だけ）
- prompts.js に `GUIDE` という定数があるので、新しいトップレベルの名前に `GUIDE` を使わない
