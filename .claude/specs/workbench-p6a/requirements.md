# 案件ワークベンチ P6a UI を gemini-kit に寄せる・gemini-kit 用カルテの書き出し — 要件

ロードマップ: `~/.claude/plans/claude-code-pc-pc-gemini-notebooklm-pc-h-imperative-newell.md` の P6.0 と P6-3

## 背景
- gemini-kit を段階的にワークベンチへ統合することになった（2026-11-26 ユーザー判断）。画面の見た目は gemini-kit に寄せる（ユーザー指示）
- 統合が終わるまでは、gemini-kit の文書づくり（要件定義書・詳細設計書・顧客提示資料）を、台帳を正にしたまま使いたい。そのために、台帳を gemini-kit の案件カルテ（anken.v2）として書き出す

## 受入条件

### UI を gemini-kit に寄せる
- [ ] AC-01 色を gemini-kit と同じ配色にする（dash.css の値）
  - 文字 #000000、ラベル #626264、背景 #F8F8FB、カード #FFFFFF、操作部品の地 #F1F1F4、線 #CCCCCC
  - 主色 #0017C1、上のバー #000060、強調の下線 #A58000、薄い強調 #E8F1FE、警告の文字 #CE0000
- [ ] AC-02 `src/styles.css` の色は `:root` の変数だけで定義する。`:root` の外に書いてよい色の値は `#fff`（濃い地の上の白文字・白地）だけ。テストで確かめる
- [ ] AC-03 字体は `Arial, "メイリオ", Meiryo, "Yu Gothic", sans-serif`、本文は 14px・行間 1.6
- [ ] AC-04 上のバーは #000060 の濃紺で、画面の上に固定する。中身の最大幅は 1600px
  - 1 段目: 名前「案件ワークベンチ」と小さな字の「オフラインで動作・外部送信なし」、案件名（または切り替え）、「＋ 新しい案件」、状態（rev・書き出しの状態）、操作のボタン
  - 2 段目: 分類のタブ。選んでいるタブは白の太字で、下に金（#A58000）の 3px の線。他のタブは #C9D4E3
- [ ] AC-05 画面のタブ（分類の中の画面）は、上のバーのすぐ下に白地の段として残す。選んでいる画面は主色の文字と下線
- [ ] AC-06 濃紺の上のバーの中のボタンは、枠が #C9D4E3・文字が白の透明なボタンにする。主色のボタン（「書き出し」と、説明用の表示中の「通常の表示に戻す」）は白地・主色の文字にする。ホバー・押せないとき・案件の切り替え（select）・rev の表示・バッジも、バーの上で読める（design.md の上書きの表）
- [ ] AC-07 文字と背景のコントラスト比は 4.5:1 以上。組み合わせは design.md の「コントラストのテスト」の一覧。テストで計算して確かめる
- [ ] AC-08 関係図・ER・ガント・S カーブの線と塗りも変数を使う。見た目の役割（線・弱い線・棒・予定線）は変えない
- [ ] AC-09 機能・画面の構成・ボタンの位置関係（どの段にあるか）は変えない。キーボードでの操作とフォーカスの見え方を保つ（濃紺の上では金の枠線）

### gemini-kit 用カルテの書き出し
- [ ] AC-10 「設定」の「書き出す」の欄に「gemini-kit 用（カルテ）を書き出す」がある。押すと `<案件名>_karte_rev<N>_<YYYYMMDD>.json` をダウンロードする
- [ ] AC-11 書き出す前のダイアログに、件数（design.md の counts）と注意（design.md の notes 1〜5 のうち当てはまるもの）を出す。「社内のみの項目を含める」は既定で外し、切り替えると件数と注意を作り直す
- [ ] AC-12 書き出した JSON を gemini-kit の `parse` → `normalize` → `validate`（`~/projects/bunsekiya-manage/gemini-kit/src/js/schema.js`）にかけると、parse の自動修正（fixes）が 0 件、validate の error が 0 件、warn は facts・decisions の「引用（quote）がありません」だけ。開発用のスクリプトで、社内のみを含める・含めないの両方と、確度の無い項目・回答済み・クローズ・取り下げを含む台帳で確かめる
- [ ] AC-13 書き出しの内容は design.md の対応表のとおり。カルテの ID は台帳の ID から決まり、同じ台帳を 2 回書き出すと同じ ID になる。取り下げ・完了・クローズの項目も消さずに状態で表す。facts・unknowns・decisions・pending・todos の各要素は元の台帳の ID を `wbId` に持つ（回答から作った事実は `QA-xxx#answer`）。最上位に `workbench`（書き出し元・revision・書き出し日時・社内のみを含めたか・ID の対応表）を持つ
- [ ] AC-14 カルテの書き出しは台帳を変えない（revision も書き出しの状態も変えない）
- [ ] AC-15 使い方の画面に、カルテの書き出しの説明（いつ使うか・gemini-kit のどこで読み込むか）を足す

## 非目標
- gemini-kit のカルテを台帳に取り込むこと（片方向だけ）
- gemini-kit 側の変更（読み込み口・検証の調整など）
- 引用（quote）を作ること。台帳は資料の原文を持たないので、quote は常に空（gemini-kit の「引用がありません」の警告は残る）
- カルテに書き出さない台帳の種別: system・meeting・change・entity・screen・interface・batch・test、関係（relations）、ベースライン、変更の記録。会議を sources にすることもしない
- sources の番号を版をまたいで同じにすること（台帳に出典の ID が無い。書き出しごとに日付・名前の順で振る）
- 中身を空に戻した案件の、前の版との ID の対応（注意を出して、別の案件名で読み込んでもらう）
- 幅 1280px 未満の上のバーの折り返しを整えること（崩れて重ならなければよい）
- カルテの issues（顧客の課題）・proposals・conflicts・asis・risks を埋めること（台帳に対応する種別が無い。P7 以降で risks などを足すときに対応を足す）
- 画面の構成・文言・機能の変更（P6a は見た目だけ）。暗い配色（ダークモード）
- gemini-kit のヘッダーにある「HTML を保存」ボタンの追加（ワークベンチは設定画面に同じ機能がある）

## 制約
- P1〜P5 と案件の操作の制約をすべて引き継ぐ（依存ゼロ・file://・通信なし・CSP・innerHTML を使わない）
- gemini-kit のファイルはワークベンチに読み込まない。検証のスクリプトはローカルにある gemini-kit を読むだけで、無ければ飛ばす（テストは gemini-kit が無くても通る）
