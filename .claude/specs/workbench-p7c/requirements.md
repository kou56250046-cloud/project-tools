## 受入条件

### 業務フロー（新しい種別 bizflow。ID の頭は BF）
- [ ] AC-01 業務フローは、現行・導入後の別（必須）と、gemini-kit と同じフロー記法の文（必須。20,000 字まで）を持つ。状態は 案・確定。関連で要件・要望・システムにつなげる
- [ ] AC-02 画面「業務フロー」（要件定義の分類）で、フローを選ぶとスイムレーンの図（部門ごとの横の帯・左から右の流れ・分岐・戻りの線・区分 AI・ルール・人・外部の色）を出す。記法の誤りは行番号つきで出し、図は誤りのある行のノードとその線を外して描ける部分だけ描く
- [ ] AC-03 同じ画面で記法を直して保存できる（画面の操作。取り消し・記録の対象）。新しいフローも作れる
- [ ] AC-04 選んだフローと関連でつながる反対側（現行なら導入後、導入後なら現行）のフローを、すべて下に縦に並べて出す
- [ ] AC-05 指示文の目的に「業務フローの作成」を足す（記法の書き方の説明を入れ、対象に選んだフローの記法を全文載せ、業務フローの追加か記法の更新を返させる）。ほかの目的の台帳の一覧には記法を出さない
- [ ] AC-06 健康診断に「記法に誤りのある業務フロー」（中）を足す

### 構成図
- [ ] AC-07 画面「構成図」（設計の分類）に、この案件のシステムを真ん中に置き、左に受信元・右に送信先のシステムを並べて連携の線（同じ相手・同じ向きは 1 本にまとめ、連携名・方式・頻度を並べる）を自動で描く。新規予定・廃止は名前の後ろの印（廃止は破線の枠）。バッチは真ん中の箱の下に一覧。連携の無いシステムは図の下に並べる。取り下げの連携・バッチは出さない
- [ ] AC-08 システム（自分以外）も連携も 0 件なら「まだありません」と出す

### 判断・データ（道具）
- [ ] AC-09 「道具」の分類に「判断・データ」の画面を足す（台帳が要る）。4 つの欄（判断フロー・判断マスタ・テーブル定義・デモのケース）に Markdown を貼るか、まとめた .md を開く。サンプルを読み込める。台帳にもブラウザにも保存しない（ロックと案件の切り替えで消す）。4 つをまとめた .md で保存できる
- [ ] AC-10 判断フローの箱に状態の印（✓ 確定 / ? 未確定 / ! マスタなし）を重ねて描く。未確定の理由は design.md の「台帳の ID の状態」の表で決まる。台帳に無い ID は警告の一覧に出し、その箱を ? にする
- [ ] AC-11 点検: 判断マスタの組み合わせの漏れと矛盾（512 通りまで）、判断フロー・判断マスタ・テーブル定義・台帳の突き合わせを出す
- [ ] AC-12 確認事項を一覧にし、CSV・md で保存できる。「台帳の質問として取り込む」で、確認事項を質問（question）の差分にして取込の画面に渡す（取込のカードで確かめて適用。題名・質問先・二重にしない決まりは design.md）
- [ ] AC-13 テーブル定義の列定義表（型は台帳の論理型）を点検の表示に出し、CSV で保存できる。「台帳のテーブルに取り込む」で、テーブル定義を台帳のテーブル（entity）の差分にして取込の画面に渡す（物理名・区分・型の対応・同じ物理名は飛ばす決まりは design.md）。取込の画面に下書きがあるときは置き換えの確認を出す
- [ ] AC-14 デモ: ケースを選ぶか値を入れて、判断フローを 1 歩ずつ（または最後まで）進め、通った道と止まった理由を図と文で出す
- [ ] AC-15 指示文の目的に 4 つを足す（判断フロー・テーブル定義・判断マスタ・デモのケース。台帳の要件・決定・質問を材料にし、Markdown を返させる。差分ではない）。参照の ID は台帳の接頭辞で書かせ、テーブル定義には物理名と区分を書かせる

- [ ] AC-17 台帳の版は 2 のまま。業務フローを持つ案件は前のツールで開くと退避に移ることを、使い方に書く

## 非目標
- 図をドラッグで直すこと・PNG / SVG で保存すること（PNG は CSP の img-src を広げる必要がある）
- Office Scripts の書き出し（Excel 側で動かす構築の手順）と、構築先（Excel・SharePoint・Dataverse）の型の対応
- 判断マスタ・判断フロー・テーブル定義・ケースを台帳に保存すること
- 構成図のネットワーク・サーバーの配置（論理の流れだけ）
- バッチを相手のシステムにつなぐこと（バッチにはシステムへの参照が無い）
- 業務フローの版の比較（差分の色分け）
- P7a・P7b の内容
- 業務フローを定例会資料・gemini-kit 用カルテ・横断・一覧の CSV に載せること
- 台帳のテーブル（entity）からテーブル定義の Markdown を作る逆の変換
- テーブル定義で台帳の既存のテーブルを更新すること（同じ物理名は飛ばすだけ）
- 点検の結果で台帳の既存の質問を回答済みにすること
- gemini-kit の記法の参照 Q・H・F・D（カルテの ID）を台帳の ID に読み替えること

## 制約
- P1〜P7b の制約をすべて引き継ぐ。gemini-kit から写すコードは、写した元をファイルの頭に書き、IIFE ごと `export const X = (() => {...})()` で包む
- 写す部品の文字列の SVG（toSVG・erSVG）は使わない。DOMParser も使わない
