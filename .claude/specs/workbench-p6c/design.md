# 案件ワークベンチ P6c 議事録の前処理・チャットのメモ・マスキング — 設計

## 1. 前処理（src/core/transcript.js・新規、DOM に触れない）
- gemini-kit の `clean.js`（clean・defiller）を写して ES module にする。`RE` → `TRANSCRIPT_RE`、`T` → `tsOf` などに付け替え
- 返す形は gemini-kit と同じ: `{ format, lines: [{ t, speaker, text }], raw: [], out, stats: { utterances, unparsed, rate, bySpeaker: [{ speaker, count, chars }] } }`
- 文字コードは csv.js の decodeBytes（UTF-8 → Shift_JIS）

画面 `src/ui/views/preprocess.js`（道具の分類「議事録の前処理」。台帳が無くても開ける。説明用の表示では隠す）:
- ファイルを選ぶか貼り付け → 結果（形式・割合・話者ごとの発言数の棒（dash.js の Dash.bar））・本文の先頭 200 行
- 「.clean.txt を保存」「コピー」「メモとして台帳に入れる」（題名・場所・期間を入れて保存。種類は「会議の文字起こし」）
- 結果は画面のモジュールの中だけに持ち、ロックで消す

## 2. チャットの読み取り（src/core/chat.js・新規）
```js
export function parseChat(text, { year }) → { format, lines: [{ at, speaker, text }], dropped, unparsed, from, to }
```
- 読む形（行ごとに当てはめ、いちばん多く当たった形を format にする）:
  | 形 | 例 |
  |---|---|
  | 角かっこの日時 | `[2026/11/20 10:23] 山田 太郎: 本文` |
  | 名前と時刻の見出し、次の行から本文（Teams の貼り付けに多い） | `山田 太郎  10:23` / `山田 太郎 2026/11/20 10:23` / `山田 太郎、10:23` |
  | 名前の行、時刻の行、本文の行（Google Chat の貼り付けに多い） | `山田 太郎` ⏎ `10:23` ⏎ `本文` |
  | 話者:本文 | `山田：本文` |
- 日付だけの行（`2026年11月20日`・`11月20日 (木)`・`2026/11/20`・`今日`・`昨日`）は、以降の発言の日付にする。年が無ければ year（既定は今年）を使う。「今日」「昨日」は貼り付けた日から決める
- 落とす飾りの行: `編集済み`・`(編集済み)`・`返信`・`n 件の返信`・`既読`・絵文字とリアクションの数だけの行（例 `👍 2`）・`さんがリアクションしました`
- 本文の続き（見出しの無い行）は前の発言につなぐ
- at は `YYYY-MM-DD HH:MM`（日付が分からなければ `HH:MM`）
- 返す lines から本文を作る: `at 話者｜本文` を 1 行ずつ（前処理と同じ形）
- どの形にも当たらない行が半分を超えたら format は 'unknown'。そのときは全体を 1 つの本文として保存できる（AC-06 の「本文のまま残す」）

## 3. 種別 memo（src/core/schema.js）
```js
memo: {
  prefix: 'MM', label: 'メモ',
  statuses: [{ v: 'active', label: '使用中' }, { v: 'archived', label: '保管' }],
  fields: {
    memoType: { type: 'enum', required: true, label: '種類', values: [{ v: 'chat', label: 'チャット' }, { v: 'transcript', label: '会議の文字起こし' }, { v: 'other', label: 'その他' }] },
    channel: { type: 'string', label: '場所（チャンネル名など）' },
    from: { type: 'date', label: '期間の始め' },
    to: { type: 'date', label: '期間の終わり' },
  },
}
```
- 本文は共通の body に入れる。50,000 字の上限は memo の body にだけかける（validateFields に memo の body の長さの検査を足す）
- 版を 3 に上げる: `SCHEMA_VERSION = 3`。migrateLedger に「版 2 → 版 3（中身はそのまま、schemaVersion だけ 3）」を足す。版 1 → 2 → 3 の順に通る
- 版 3 の台帳を古いツールで開くと「新しい版です」で読めない（今の migrateLedger の決まりどおり）。これは書き出しのファイルを新しいツールで開けば済む
- memo を対象外にするところ:
  - 健康診断: 出典なし・推測のままなど、項目ごとの点検から memo を外す
  - 一覧・関係図: memo を出さない（メモの画面だけで扱う）
  - gemini-kit 用カルテ・ダッシュボード: 種別を名前で選んでいるので、何もしなくても入らない（テストで確かめる）
  - 説明用の表示: `visibleLedger(ledger, true)` で memo も外す（社内のみと同じ扱い）
  - 指示文の「台帳の状態」: memo の本文は入れない（大きいため）。メモからの取込のときだけ、選んだメモを入れる
  - 使い方の流れ図の進み具合（initial の判定）: memo は数えない

## 4. メモの画面（src/ui/views/memos.js・新規）
- 分類は「把握」。台帳が要る。説明用の表示では隠す
- 上: 「チャットを貼り付けてメモにする」（題名・種類・場所・タグ・貼り付けの欄 → 「読み取る」→ 日時・発言者・本文の表と、落とした行・読めなかった行の数 → 「メモとして保存」）
- 下: メモの一覧（種類・場所・期間・タグで絞り込み、チェックで選ぶ）。押すと詳細パネル（本文は textContent の pre）
- 選んだメモを「JSON で書き出す」「md で書き出す」「メモからの取込の指示文を開く」
- 保存は store.applyLocal の add（取り消し・記録・revision の対象）

書き出しの形:
```json
{ "type": "memo-export", "from": "案件ワークベンチ", "project": "案件名", "exportedAt": "…",
  "memos": [{ "id": "MM-001", "title": "…", "memoType": "chat", "channel": "…", "from": "2026-11-01", "to": "2026-11-20", "tags": [],
              "lines": [{ "at": "2026-11-20 10:23", "speaker": "山田 太郎", "text": "…" }] }] }
```
- md は メモごとに `## 題名（場所・期間）` と本文
- lines は本文の行（`at 話者｜本文`）を分けて作る。分けられない行は `{ "text": 行 }`
- ファイル名は `<案件名>_memo_<YYYYMMDD>.json`。.gitignore に `*_memo_*.json` を足す（実案件のデータをコミットしない）

## 5. 指示文「メモからの取込」（src/core/prompts.js・src/ui/views/prompts.js）
- PURPOSES に `{ id: 'memo', group: '作る', label: 'メモからの取込', desc: '選んだメモ（チャット・文字起こし）から、決定・課題・質問を足し、既存の質問の回答や課題の状態を更新する', kinds: [] }`
- 指示文の画面で、テスト観点の生成と同じ「対象を選ぶ」欄に memo を出す（対象の候補を purpose ごとに決める形に広げる）
- 本文は「ここから資料」の下に、メモごとに題名・場所・期間・本文を入れる。合計 60,000 字を超えたら、選び直すよう出す（Gemini に貼れる大きさの目安）

## 6. マスキング（src/core/mask.js・新規、src/ui/views/mask.js・新規）
- gemini-kit の `mask.js`（RULES・infer・apply・newState・mappingCSV・seqFormat・toTSV・toCSV）を写す。`num` → `maskNum`、`apply` → `applyMask`、`check` → `maskCheck` に付け替え
- 表の読み取り: gemini-kit の parseTable（1 行目にタブがあれば TSV、行の長さを最長にそろえる、空行を落とさない）を残す。csv.js の parseDelimited とは「空行と行の長さ」の扱いが違うため、mask.js の中に `parseMaskTable` として持つ
- ファイルは P6b の読み取り（xlsx・csv）を使う。xlsx は 1 つのシートを選ぶ
- 画面（道具の分類「マスキング」。台帳が無くても開ける。説明用の表示では隠す）:
  - 上: 貼り付けかファイル、「1 行目は見出し」「文中の値も置き換える」のチェック
  - 中: 列ごとの伏せ方の選択（自動で選んだものが初期値）
  - 下: 伏せた表の先頭 50 行、警告、「TSV を保存」「CSV を保存」「コピー」「対応表を CSV で保存」
- 対応表と辞書（newState）は画面のモジュールの中だけ。ロックで消す。同じ画面の中で続けて伏せると、同じ仮名を使う（gemini-kit と同じ）

## 検討した代替案
| 案 | 採らなかった理由 |
|---|---|
| メモを台帳の外（別の保存）に置く | 暗号化の箱が 2 つになり、合言葉の変更・退避・書き出しの扱いが増える。台帳の中なら取り消し・案件ごとの切り替え・暗号化がそのまま効く |
| メモの発言を構造（配列）で保存する | 新しいフィールドの型と検査が要る。本文の行（`at 話者｜本文`）から書き出すときに分ければ足りる |
| 版を 3 に上げる | （レビューを受けて取りやめ）古いツールで同じ保存を開くと、メモの無い案件まで退避に移る。移行で全案件が未書き出しになる。既存のサンプルとテストも直しが要る。種別を足すだけなら今の版のままで読める |
| チャットの形をユーザーの実物で決めてから作る | 実物は案件のデータなので持ち出せない。よくある形で作り、ダミーの貼り付けでテストし、合わない形は「読めなかった行」の数で気づけるようにする |

## レビューを受けて決めたこと（上の本文と食い違うときは、こちらが正）

### 版は上げない（指摘 1・確認事項 101・102）
- `SCHEMA_VERSION` は 2 のまま。memo を KINDS に足すだけにする。今のサンプル・テスト・書き出しのファイルはそのまま使える
- 古いツールで同じ保存を開いたとき: メモを持つ案件だけが「読めない案件」になって退避に移る（消えない）。新しいツールで開き直せば、設定の退避から書き出して読み直せる。この動きを使い方の「よくある困りごと」に書く
- AC-11 を「版は 2 のまま。memo を持たない台帳は前のツールでも読める」に置き換える

### 台帳の項目として扱う種別（指摘 2）
- schema.js に `LEDGER_KINDS`（KIND_IDS から memo を除いたもの）を 1 つ置く。memo を出さない処理はすべてこれを使う
- 使う場所と扱い:
  | 場所 | 扱い |
  |---|---|
  | prompts.js の schemaText | LEDGER_KINDS だけを説明する（Gemini に memo を教えない） |
  | prompts.js の itemsText | memo の行は出さない（題名も出さない） |
  | prompts.js の notebookPrompt | memo を出さない |
  | patch.js の validatePatch | kind が memo の add・memo の ID への update・relate は誤り「メモは差分で足したり変えたりできません」 |
  | impact.js | links をたどるとき memo を通らない・結果に入れない（変更要求書・変更の影響レビューに出ない） |
  | health.js | 項目ごとの点検（出典なし・推測のまま・担当期限など）から memo を外す。存在しない ID への参照の点検は memo も対象のまま（壊れた参照は見つけたい） |
  | overview.js | 種別ごとの件数・始め方の判定（10 件未満）に memo を数えない |
  | list.js | 種別の選択肢と一覧に memo を出さない |
  | graph.js | 直しは不要（もともと関係者とシステムだけ） |
  | karte.js・dashboard.js・guide-flow.js | 種別を名前で選んでいるので直しは不要（テストで確かめる） |
  | visibleLedger（説明用の表示） | memo を除く。memo を指す links は、社内のみの項目を指すときと同じ扱い（今の表示のまま） |
- 指示文の「台帳の状態」には memo を一切出さない（T2 の文言もこれに合わせる）

### メモからの取込の指示文（指摘 3）
- PURPOSES の `memo` は kinds を持たない（minutes と同じく、memo を除く全種別を一覧に載せる。既存の ID が見えるので回答・状態の更新もできる）
- 選んだメモは `promptState.memoIds` に持つ（テスト観点の生成の targetIds とは分ける）
- 60,000 字は「選んだメモの本文の合計」。超えたら指示文を作らず、選び直すよう出す
- Gemini には、取り込む項目の出典を `{ type: 'chat', ref: メモの題名, date: 発言の日 }` で書かせる（メモの ID は links に入れさせない）

### チャットの読み取り（指摘 4）
```js
export function parseChat(text, { year, today }) → { format, lines: [{ at, speaker, text, raw? }], dropped, unparsed, from, to }
```
- today（YYYY-MM-DD）は「今日」「昨日」と、年の無い日付の年を決めるのに使う。年の無い日付の月が today の月より 2 か月以上先なら前の年とみなす（12 月から 1 月をまたぐ場合）
- 手順:
  1. 飾りの行（design.md §2 の一覧）を落とし、dropped に数える。空行は区切りとして扱う
  2. 日付だけの行を見つけ、以降の発言の日付にする
  3. 形を決める: 4 つの形それぞれで「発言の始まり」に当たる行を数え、いちばん多い形を format にする（同数なら表の上の形）。当たる行が 0 なら format は 'unknown'
  4. 決めた形だけで全体を読み直す。発言の始まりの行で新しい発言を始め、それ以外の行は前の発言の本文に空白 1 つでつなぐ（1 行 1 発言を保つ）
  5. 最初の発言より前の行は `{ at: '', speaker: '', text, raw: true }` として残し、unparsed に数える
- 発言の始まりの見分け方:
  | 形 | 発言の始まりの行 |
  |---|---|
  | 角かっこの日時 | `^\[(\d{4}/\d{1,2}/\d{1,2} )?\d{1,2}:\d{2}\] (.{1,30}?)[:：] ?(.*)$` |
  | 名前と時刻の見出し | `^(.{1,30}?)[\s、,]+((\d{4}/\d{1,2}/\d{1,2} )?(午前|午後)?\d{1,2}:\d{2})$`（本文は次の行から） |
  | 名前・時刻・本文の 3 行 | 次の空でない行が時刻だけ（`^(午前|午後)?\d{1,2}:\d{2}$`）の行。その行が名前、時刻の次の行から本文 |
  | 話者:本文 | `^(.{1,20}?)[:：](.+)$`。この形が format に選ばれたときだけ使う（他の形のチャットの本文にある「注意：…」を発言の始まりにしないため） |
- 1 行 1 発言の本文の形と、分け直す決まり（書き出しの lines を作るとき）:
  - 1 行は `at 話者｜本文`（at が無ければ `話者｜本文`）。前処理の `時刻 話者｜本文` と同じ
  - 分け方: 最初の `｜` で左右に分ける。左の先頭が `^((\d{4}-\d{2}-\d{2} )?\d{1,2}:\d{2}(:\d{2})?) ` に当たればそれが at、残りが話者（空白を含んでよい）。右が本文（本文の中の `｜` はそのまま）
  - `｜` が無い行は `{ text: 行 }`
- 例（テストの期待値にする）:
  | 形 | 入力 | 期待する lines |
  |---|---|---|
  | 角かっこ | `[2026/11/20 10:23] 山田 太郎: 了解です` | `[{ at: '2026-11-20 10:23', speaker: '山田 太郎', text: '了解です' }]` |
  | 見出し | `11月20日 (木)` ⏎ `山田 太郎  10:23` ⏎ `明日の件` ⏎ `よろしく` ⏎ `編集済み` | `[{ at: '2026-11-20 10:23', speaker: '山田 太郎', text: '明日の件 よろしく' }]`、dropped 1 |
  | 3 行 | `山田 太郎` ⏎ `10:23` ⏎ `資料を送りました` ⏎ `👍 2` | `[{ at: '10:23', speaker: '山田 太郎', text: '資料を送りました' }]`、dropped 1（日付の行が無いので時刻だけ） |
  | 話者:本文 | `山田：確認します` ⏎ `佐藤：お願いします` | `[{ at: '', speaker: '山田', text: '確認します' }, { at: '', speaker: '佐藤', text: 'お願いします' }]` |
  | 読めない | `こんにちは` ⏎ `よろしく` | format 'unknown'、lines は 2 行とも raw |
- 時刻の `午前・午後` は 24 時間に直す

### 保存の大きさとメモを消す（指摘 5）
- メモは消せるようにする: ローカルの操作 `{ op: 'remove', id }` を足す（applyLocalOps だけ。kind が memo のときだけ許す。Gemini の差分では使えない）。取り消し・変更の記録・revision の対象。メモを指す links は消すときに外す
- 上限:
  - 1 つのメモの本文は 50,000 字（JS の文字列の長さで数える。絵文字は 2）
  - 案件ごとのメモの本文の合計が 300,000 字を超えたら、メモを足す前に「メモの合計が多くなっています。要らないメモを書き出して消してください」と警告する（保存の中ではおよそ 4 倍になり、ブラウザの保存の上限 5MB に近づくため）。合計は設定の「ブラウザの保存の大きさ」の欄にも出す
- AC-07 をこの 2 つに置き換える

### 非目標と受入条件の振り分け（指摘 6）
- 受入条件に入れる（手間が小さい）:
  - 前処理で複数のファイルを一度に選べる（ファイルごとに結果を出す）
  - マスキングの「対応表を空にする」ボタン
- 非目標に入れる:
  - 書き出したメモの JSON を読み込んで台帳に戻すこと
  - 読み取った行を保存する前に画面で直すこと
  - 同じ期間を 2 回貼ったときの重なりを除くこと
  - メモの本文をあとから編集・分割・結合すること（消して作り直す）
  - ファイル名から日付・回を推定すること
  - Gemini の差分でメモを足す・変えること
