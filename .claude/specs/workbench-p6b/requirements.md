# 案件ワークベンチ P6b 資料の変換（md 化と表の下ごしらえ） — 要件

ロードマップ: `~/.claude/plans/claude-code-pc-pc-gemini-notebooklm-pc-h-imperative-newell.md` の P6-1

## 背景
- NotebookLM は PDF・画像が苦手で、HTML・PowerPoint・Excel は読めない（ユーザー）。資料を忠実な Markdown にして渡したい
- gemini-kit には、表（Excel・CSV・JSON）を NotebookLM 用の一式にする「表の下ごしらえ」がある（xlsx.js・tableprep.js・prepui.js）。Word・PowerPoint・HTML を md にする処理は gemini-kit にも無い（調査で確認）
- PDF・画像は依存ゼロでは文字を取り出せない。Gemini に、先に選択肢つきで確かめさせてから md を返させる（ユーザーの案）

## 受入条件

### 画面
- [ ] AC-01 「道具」の分類に「資料の変換」の画面を足す。台帳が無くても、ロック中でなければ使える（台帳に保存しないため）
- [ ] AC-02 ファイルを選ぶかドロップする（複数可）。形式はファイルの中身で判定し、判定できない形式は理由を出して断る
- [ ] AC-03 変換したものは台帳にもブラウザにも保存しない。画面に、ファイルごとの md の先頭（最大 200 行）と文字数を出し、「md を保存」「コピー」「全部を zip で保存」ができる
- [ ] AC-04 md の先頭に出典の情報を入れる: 元のファイル名・変換した日・変換の方式（このツール / Gemini）・形式ごとの数（design.md の「数える項目」の表）

### ブラウザの中で変換する形式
- [ ] AC-05 Excel（.xlsx・.xlsm）: シートごとに見出し（`## シート名`）と md の表。日付の書式のセルは YYYY-MM-DD（時刻があれば YYYY-MM-DD HH:MM、時刻だけなら HH:MM）。数式は保存されている値。結合セルは左上の値だけ。.xls・パスワード付き・壊れたファイルは理由を出して断る
- [ ] AC-06 CSV・TSV（UTF-8 / Shift_JIS / UTF-16 の BOM つきを判定）と JSON（オブジェクトの配列、または配列を持つキーごと。safeParse で読む）: md の表。.md・.txt はそのまま通し、頭書きだけ付ける
- [ ] AC-07 Word（.docx）: 見出しのスタイル（見出し 1〜6・Heading 1〜6・タイトル）を `#` の段に、箇条書き・番号つきの段落を `-` と `1.` に、表を md の表にする（結合セルは空のセルで埋めて列の位置を保つ）。本文の順を保つ。テキストボックスも本文に出し、同じ文字を二重に出さない。図は `[図]` の印だけ残す
- [ ] AC-08 PowerPoint（.pptx）: スライドの並び順（presentation.xml の順）で `## スライド N: タイトル`、本文の段落を段の深さつきの `-`、表を md の表、ノートを `> ノート:` で入れる。図・SmartArt・グラフは `[図]`。非表示のスライドも「（非表示）」を付けて出す
- [ ] AC-09 HTML（.html・.htm）: 見出し・段落・箇条書き・表・リンク（文字と URL）・整形済みの文を md にする。閉じタグを省略した HTML も読む。表の結合セルは空のセルで埋める。画像は `[図]`（alt があれば `[図: alt]`）。script・style・head の中は捨てる
- [ ] AC-10 表の形式（Excel・CSV・JSON）では、「NotebookLM 用の一式（表の下ごしらえ）」も選べる。シート（Excel）か配列のキー（JSON）を 1 つ選び、gemini-kit と同じ中身（項目定義書・集計・代表サンプル・行数で分けたデータ）と同じ選択肢（まとめる列・形式・行数・1 ファイルにまとめる・JSON の拡張子）で zip に保存する

### PDF・画像（Gemini に任せる）
- [ ] AC-11 PDF・画像（png・jpg・gif・bmp・webp）を選ぶと、Gemini に貼る「変換の指示文」を作る。指示文は、Gemini にまず選択肢つきの確認（表の扱い・図の説明の要否・見出しの段・ページの区切りの印を残すか・読み取れない文字の扱い）をさせ、答えを受けてから、要約せずに忠実な md を返させる
- [ ] AC-12 返ってきた md を貼ると点検する（何回かに分かれた返事をつなげて貼ってよい。```の囲みは外す）: ページの区切りの印から抜けたページ（入力したページ数と比べる。PDF のときはツールが数えた数を初期値にする。印が 1 つも無ければ点検しない）、表の数、見出しの数、「[読めない]」の数を出す。点検した md に出典の情報を付けて保存できる

## 非目標
- PDF・画像の文字をブラウザの中で取り出すこと（OCR・PDF の文字の抽出）
- .doc・.ppt・.xls（古い形式）、パスワード付き、ZIP64 の大きなファイル
- Word・PowerPoint の書式（色・太字・字の大きさ）、図の中身、グラフのデータ、コメント・変更履歴、脚注
- 変換した md を台帳に入れること（取り込みは今までどおり指示文と差分で行う）
- 変換した md を NotebookLM や Google ドライブへ送ること（ダウンロードかコピーまで）
- マスキング（P6c）
- 1 ファイル 30MB を超えるファイル（断る）
- Excel 方眼紙（帳票の形の設計書）を見やすく整えること。表としてそのまま出す
- Word・PowerPoint のヘッダーとフッター、Word の中のリンクの URL（文字だけ出す）
- 非表示のシートを区別すること（全部のシートを出す）
- .mht・.mhtml（断る）、1904 年起点の日付（Mac の Excel）
- 暗号化（パスワード・秘密度ラベル）されたファイル（断る）

## 制約
- P1〜P6a の制約をすべて引き継ぐ（依存ゼロ・file://・通信なし・CSP をハッシュで・innerHTML を使わない・属性に style を書かない）
- 変換の処理は DOM に触れない `src/core` に置き、node --test で確かめる（HTML の読み取りも DOMParser を使わずに書く）
- gemini-kit から写すコードは、写した元をファイルの頭に書き、ES module に書き直す。名前の衝突（dec・TOP・num など）は付け替える
