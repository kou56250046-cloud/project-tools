## 背景
- 網羅の点検で「案件の体制」が足りなかった（関係者の一覧と関係図はあるが、体制図と、誰が実行・承認するかの表が無い）
- ヒヤリングで「体制図と RACI 表」を足すと決めた（2026-11-26）

## 受入条件

### 体制
- [ ] AC-01 関係者に「上長（報告先）」（関係者を指す）と「体制上の役割」（責任者・PM・PL・担当・承認者・窓口・その他）を足す。上長の循環は誤りにする。詳細パネルで選んで変えられる（取り消しの対象）
- [ ] AC-02 画面「体制」（把握の分類）に体制図を出す: 立場（顧客・自社・協力会社）ごとの列の中で、所属ごとにまとめ、上長 → 部下の木で並べる。箱には名前・役割・体制上の役割。上長が別の列にいる線も引く。箱を押すと詳細パネル
- [ ] AC-03 健康診断に「上長が関与なしの関係者」（低）を足す

### RACI
- [ ] AC-04 作業・決定・課題に RACI（関係者と R・A・C・I の組の一覧）を足す
- [ ] AC-05 RACI は役ごとに補って見せる（保存はしない）: 明示に R が無ければ作業・課題の担当を R、明示に A が無く決定の決めた人がちょうど 1 人ならその人を A。補った印は表で薄く出す（design.md の「補いと明示の規則」）
- [ ] AC-06 画面「体制」に RACI 表を出す: 行と列は design.md の「画面の操作」のとおり。セルを押すと 空 → R → A → C → I → 空 と変わり、明示の役だけを台帳に保存する（取り消し・記録の対象）。説明用の表示では押せない
- [ ] AC-07 健康診断に足す:
  - 「A（承認者）のいない工程」（低）: 子を持つ根の作業で、完了・中止でなく、A が明示も補いも無いもの
  - 「決める人のいない課題」（低）: 重要度が高の未完了の課題で、A が無いもの
  - 「A が 2 人以上いる項目」（中）: 明示の A だけを数える
- [ ] AC-08 指示文の目的に「体制の整理」を足す（関係者の一覧を載せ、上長・体制上の役割の更新と、作業・決定・課題の RACI を返させる）
- [ ] AC-09 指示文の種別の説明と台帳の一覧で、RACI が「SH-001:R, SH-002:A」の形で読める（[object Object] にならない）。Gemini の差分の update で RACI から人が消えるとき、取込のカードに消える人の名前を出す

## 非目標
- 体制図をドラッグで並べ替えること・画像で保存すること
- 1 人が複数の所属を持つこと（兼務）・期間で変わる体制（体制の版）
- RACI の行に要望・要件・テストを入れること
- 補った R・A を台帳に書き込むこと（表で押したときだけ保存する）
- 工数・稼働率の割り当て
- 担当や決めた人を変えたときに、明示の RACI を合わせて直すこと
- A を 1 人に限ること（誤りにはしない。健康診断の指摘だけ）
- RACI 表・体制図を CSV・Excel・印刷用に書き出すこと
- P7a・P7c の内容
