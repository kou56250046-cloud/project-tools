# 案件ワークベンチ P2（要件定義を回す） — 要件

ロードマップ: `~/.claude/plans/claude-code-pc-pc-gemini-notebooklm-pc-h-imperative-newell.md`
前提: P1（`.claude/specs/workbench-p1/`）と P1 レビュー修正（FIX-001〜018）が済んでいる。

## 背景

- P1 で台帳と Gemini との往復はできたが、要件定義の会議を回すための道具が無い
  - 次のヒヤリングで何を聞くかを、未確定・空欄から自分で拾い出している
  - 質問・課題が「誰の返事待ちか」「何日止まっているか」が見えない（SIer の遅延の典型は顧客の返事待ち）
  - 非機能要件の抜けに気づくのが遅れる
  - 合意した範囲の後から増えた要望が、範囲内なのか追加費用なのかの判断と根拠が残らない
- P3〜P5 でも使う共通の仕組み（台帳の版の移行・画面の分類・変更の記録）をここで入れる

## 受入条件

### 共通基盤（P3〜P5 も使う）
- [ ] AC-C1 台帳の版を 2 に上げる。版 1 の台帳（ブラウザ内の保存・書き出したファイル）を開くと、自動で版 2 に移行され、内容は失われない。移行に失敗したときは P1 の退避の仕組みで元のデータが残る
- [ ] AC-C2 画面の切り替えを2段にする。上段は「把握 / 要件定義 / 計画・進捗 / 設計 / テスト / 道具」の分類、下段はその分類の画面。P1 の画面はすべてどこかの分類にある
- [ ] AC-C3 差分の適用・画面での変更のたびに、変更の記録（いつ・どこから・どの項目を追加/更新したか・状態の変化）が台帳に残る。記録は新しい 2,000 件まで保つ
- [ ] AC-C5 項目をまたぐ誤り（循環など、P3 以降で足す検査を含む）を含む変更は、取込でも画面の変更でも適用できない。読み込んだ台帳にあった場合は開いたうえで健康診断に「高」として出す
- [ ] AC-C6 links は向きを持たない（どちらの項目の links に入っていても、つながっているとみなす）
- [ ] AC-C4 指示文の項目一覧は、目的に関係する種別だけを載せられる（目的ごとに定義）。全種別を載せる目的は P1 と同じ

### ヒヤリングの循環
- [ ] AC-01 種別「会議」（MT）を足す。日付・種類（定例 / ヒヤリング / レビュー / その他）・出席者（関係者 ID）・議題を持つ
- [ ] AC-02 質問に「どの会議で聞くか」（会議 ID）と「聞いた日」を持てる
- [ ] AC-03 ヒヤリング画面で会議を選ぶと、その会議で聞く質問の一覧（ヒヤリングシート）が出る。未割り当ての未回答質問を一覧から足せる
- [ ] AC-04 「次のヒヤリングの候補」を自動で出す: 未回答で会議が決まっていない質問、健康診断で見つかった空欄（担当・期限・出典なし、推測のまま）、非機能の未定義の大項目。候補を選んで会議に割り当てられる
- [ ] AC-05 ヒヤリングシートの各質問に、その場で回答を入力し「回答済み」にできる（入力はこの画面の質問の answer・status・聞いた日に限る）。この変更も取り消しと変更の記録の対象
- [ ] AC-06 指示文の目的「ヒヤリング質問の生成」を足す。台帳の未確定・空欄・矛盾から、聞くべき質問を作らせる
- [ ] AC-07 会議を選んで「議事録の取込」の指示文を作ると、その会議の出席者・議題・ヒヤリングシートの質問が指示文に入り、Gemini は回答を該当の質問 ID への update として返すよう指示される

### 質問・課題とボール管理
- [ ] AC-08 未完了の質問・課題ごとに「ボール」（誰の対応待ちか）を出す。質問は質問先、課題は担当の立場（顧客 / 自社 / 協力会社）から決まる。相手が決まっていないものは「未定」
- [ ] AC-09 待ち日数を出す。質問は「聞いた日」（無ければ作成日）から、課題は作成日から今日までの日数。予定の会議に割り当て済みで聞いた日が無い質問は「まだ聞いていない」としてボールを自社にし、待ち日数を出さない
- [ ] AC-10 課題・質問画面で、ボールの持ち主ごと（顧客待ち / 自社待ち / 協力会社待ち / 未定）に件数と一覧を出す。待ち日数の長い順に並ぶ
- [ ] AC-11 顧客待ちが 7 日以上の質問・課題を、健康診断で「中」として出す（日数は設定で変えられる。既定 7）

### 非機能要求グレード
- [ ] AC-12 要件に「非機能の大項目」を持てる（IPA 非機能要求グレードの 6 大項目: 可用性 / 性能・拡張性 / 運用・保守性 / 移行性 / セキュリティ / システム環境・エコロジー）
- [ ] AC-13 非機能の画面で、6 大項目ごとに、紐づく要件（nfrCategory が一致する非機能要件）・未回答の質問（nfrCategory が一致する質問）・状態（未着手 / 質問中 / 定義あり / 合意済み）を表で出す。質問にも nfrCategory を持てる
- [ ] AC-14 要件も未回答の質問も無い大項目を、健康診断で「中」として出す
- [ ] AC-15 指示文の目的「非機能の洗い出し」を足す。大項目ごとの代表的な確認点（中項目の例）を指示文に入れ、要件案と質問を返させる

### スコープ管理
- [ ] AC-16 要望と要件に「範囲」（範囲内 / 範囲外 / 未判断）と「範囲の判断理由」を持てる
- [ ] AC-17 スコープ画面で「ベースラインを記録する」と、その時点の要望・要件の ID・題名・範囲を名前と日付つきで台帳に残せる（複数回可）
- [ ] AC-18 最新のベースラインの後に追加された要望・要件を、スコープ画面と一覧で「ベースライン後」と表示する
- [ ] AC-19 スコープ画面で、ベースラインと今の差（追加・範囲の変更・取り下げ）を一覧で出す
- [ ] AC-20 健康診断に次を足す: 範囲外なのに判断理由が無い（中）、ベースライン後に追加されて範囲が未判断（中）
- [ ] AC-21 要望・要件の範囲は、詳細パネルから変更できる（範囲と理由に限る）

## 非目標

- 会議の日程調整・招待・カレンダー連携
- 議事録そのものの作成（Gemini と Meet の自動メモに任せる。ここは取り込みだけ）
- 非機能要求グレードの中項目・小項目・レベル値の管理（大項目の単位まで。中項目は指示文の確認点として使うだけ）
- ベースラインどうしの差（ベースラインと「今」の差だけ）
- 範囲外の追加費用の計算（P3 の変更管理・P4 の見積で扱う）
- 項目の自由なフォーム編集（P1 と同じ。今回の例外は AC-05・AC-21 の項目だけ）
- ボールの手動での付け替え（立場から自動で決める）
- 変更の記録の閲覧画面（P3 の定例会資料で使う。記録を残すところまで）
- 複数の台帳（P5）

## 制約

- P1 の制約をすべて引き継ぐ（依存ゼロ・単一 HTML・file:// で動作・外部通信なし・暗号化して保存・textContent のみ）
- 版 1 の台帳を読めなくしない。移行は `schema.js` の `migrateLedger` 1か所で行う
- 既存の種別・項目の意味を変えない（足すだけ）
