# 案件ワークベンチ

SIer の PM/SE が1人で使う、案件台帳のツールです。
関係者・システム・要望・制約・要件・決定・課題・質問を、ID でつないだ1つの台帳として持ちます。

- HTML ファイル1つで動きます。インストール不要、ダブルクリックで開けます
- **外部と一切通信しません。** ブラウザのセキュリティ設定（CSP）で通信を禁止しています
- Gemini との受け渡しはコピーと貼り付けだけで行います

```
[指示文] ──コピー──▶ Gemini（＋資料・議事録）
                          │ 差分JSON
[取込]  ◀──貼り付け────────┘
   │ 1件ずつ確認して適用
   ▼
[台帳] → 概要 / 関係図 / 一覧 / 決定ログ / 健康診断
```

---

## 入手する

1. 配布ページ（GitHub Pages）を開く
2. 「設定」画面の「HTML をダウンロード」を押す
3. 保存した `anken-workbench.html` をダブルクリックで開く

以後はダウンロードしたファイルだけで使えます。新しい版が出たら、同じ手順で入れ替えます。
台帳はブラウザに残るので、入れ替えても消えません。念のため、入れ替える前に書き出しておいてください。

## 会社PCでの使い方

### 1. 案件を作る
「設定」→「新しい案件を作る」。案件の型「業務システム新規」を選ぶと、標準のヒヤリング質問が20件入った状態で始まります。

### 2. 資料から最初の台帳を作る
1. 「指示文」で **初期作成** を選び、「指示文をコピー」
2. Gemini に貼り、末尾の `--- ここから資料 ---` の下に提案依頼書やメモを貼って送る
3. 返答をまるごとコピーし、「取込」に貼って「読み取る」
4. カードを1件ずつ確かめ、要らないものは「却下」にして「適用」

### 3. 会議のあと
「指示文」→ **議事録の取込**。決定・課題・質問が足され、回答が出た質問は「回答済み」に更新されます。

### 4. 節目ごとにレビュー
「指示文」→ **レビュー**。5つの立場から台帳を点検させ、指摘を課題・質問として取り込みます。

| 立場 | 見るところ |
|---|---|
| エンジニア | 技術的に実現できるか、非機能、既存システムとの連携、移行、テストの前提 |
| PL | 設計や作業に落とせる細かさか、矛盾と抜け、担当・期限 |
| PM | 予算・期間・範囲、顧客との合意、意思決定の遅れ、体制 |
| 利用者 | 入力の手間、例外的な業務、繁忙期、画面や帳票の使われ方 |
| 運用者 | 障害対応、バックアップ、マスタと権限の保守、問い合わせ窓口 |

### 要件定義を回す（分類「要件定義」）
- **ヒヤリング**: 会議を選ぶと、その会議で聞く質問の一覧（ヒヤリングシート）が出ます。下の「次のヒヤリングの候補」（会議の決まっていない質問・台帳の空欄・非機能の未着手）を選んで割り当てられます。会議中はその場で回答を書いて「回答済みにする」。会議の後は「この会議の議事録の指示文を作る」で、出席者と聞いた質問が入った指示文を Gemini に渡せます
- **課題と質問**: 未完了の課題・質問を「顧客待ち / 自社待ち / 協力会社待ち / 未定」に分け、待ち日数の長い順に並べます。予定の会議に割り当てただけでまだ聞いていない質問は「自社（まだ聞いていない）」です
- **非機能**: IPA 非機能要求グレードの 6 大項目ごとに、要件と質問の状況（未着手 / 質問中 / 定義あり / 合意済み）を出します。「非機能の洗い出し」の指示文で要件の案と質問を作れます
- **スコープ**: 顧客と合意した時点で「ベースラインを記録する」。その後に増えた要望・要件は「ベースライン後」と表示され、範囲（範囲内 / 範囲外 / 未判断）と理由を詳細パネルで残せます
- 顧客待ちを知らせる日数は「設定」の「この案件の設定」で変えられます（既定 7 日）

### 計画・進捗・報告（分類「計画・進捗」）
- **WBS**: 「WBS の作成」の指示文で、要件から作業を洗い出させて取り込みます。親の作業の見積・実績・進捗は子から自動で集計します。末端の作業は進捗と実績を表の中で直接入力できます
- **ガント**: 週 / 月の幅で切り替え。今日の線・進捗・マイルストーン（◆）・前の作業からの矢印が出ます。期間の経過に対して進捗が 20 ポイント以上遅れている作業は赤枠と「遅れ」の文字で出ます
- **進捗（EVM）**: 工数（人日）で BAC・PV・EV・AC・SPI・CPI・EAC と S カーブを出します。SPI か CPI が 0.9 未満になると健康診断に出ます。週次の報告は「進捗の更新」の指示文で取り込めます
- **変更管理**: 変更要求を押すと、影響範囲（対象から 2 段まで）と影響する作業の見積の合計が出ます。変更要求書の下書きをコピーでき、「変更の影響レビュー」の指示文で Gemini に見落としを指摘させられます
- **定例会資料**: 前回の定例から今日までの、完了・追加・決定・顧客の返事待ち・遅れ・次回までの作業を1画面にまとめます。「週報の文面をコピー」でメールに貼れる文面になり、「週報の清書」の指示文で Gemini に整えさせられます

### 設計と見積（分類「設計」）
- **データ設計**: 「データ設計」の指示文で、要件からテーブルと列を作らせて取り込みます。ER 図（左が参照される側）・テーブル定義・DDL（PostgreSQL / SQL Server / Oracle を選んでコピー）・物理名の点検（規則・予約語・Oracle の 30 文字）が出ます。テーブルを更新する差分は列を丸ごと置き換えるので、取込のカードに「消える列」が警告で出ます
- **画面・連携 / CRUD**: 「画面・連携の洗い出し」の指示文で、画面・連携・バッチとそれぞれの CRUD を作らせます。CRUD 表で、どの機能からも作成されないテーブル・どの機能も触らないテーブルに印が付きます
- **見積（FP）**: NESMA 概算法の FP を自動で数えます。生産性（人日 / FP）を入れると、WBS の見積（BAC）と比べ、差が ±30% を超えると健康診断に出ます
- **マスタ点検**: マスタのテーブルを選び、CSV / TSV を貼るかファイルを選ぶと、見出し・主キーの重複・必須の空欄・型と長さ・コードの形・参照先に無い値を点検します。Shift_JIS のファイルも読めます。**元データは保存しません**（画面を離れると消えます）

### テスト（分類「テスト」）
- **トレーサビリティ**: 要件ごとに、つながる要望・設計（画面・連携・バッチ・テーブル）・テストと判定（テストなし / 不合格あり / 未実施あり / すべて合格）を表で出します。設計の項目につながるテストも、その要件のテストとして数えます。判定と工程で絞り込めます
- **テスト**: 工程・観点・状態で絞り込める一覧と、工程ごとの合格率。状態と実施日は表で直接変えられます
- 「テスト観点の生成」の指示文で、要件や画面を選ぶと、その項目（必須・型）から境界値・異常系・権限などのテストを作らせられます

### 複数の案件
- 「設定」で新しい案件を作ったりファイルを読み込んだりすると、案件が追加されます（今の案件は残ります）。同じ案件名のファイルを読み込むと、「置き換える / 別の案件として足す」を選べます
- 上部の案件名から切り替えます。合言葉はすべての案件で共通です。取り消しと「未書き出し」の印は案件ごとです
- 「設定」の「この案件の設定」で「自分」を選んでおくと、分類「把握」の「横断」に、全案件の自分の作業（14 日以内に終わる予定・期限切れ）・自分が持つボール・顧客の返事待ちがまとまって出ます
- 案件の型は「業務システム新規」「基幹システム刷新」「パッケージ導入」の 3 つです。どれも非機能の 6 大項目の質問が入っています
- 使わなくなった案件は、書き出してから「ブラウザから外す」で外せます。保存の大きさは「設定」に出ます（4 MB を超えると警告）

### 顧客に画面を見せるとき
- 上部の「説明用の表示」を押すと、「社内のみ」にした項目とそれへの参照、健康診断、実績の値（実績・AC・CPI・EAC）、課題の重要度、道具の画面（指示文・取込・設定）を隠します
- 項目を「社内のみ」にするには、詳細パネルの「社内のみ」に印を付けます
- 説明用の表示は保存しません。開き直すと通常の表示に戻ります

### 5. 毎日の確認
「概要」の **次にやること** と「健康診断」を見ます。期限切れ、担当のない課題、出典のない項目、推測のまま放置された項目などを、AI を使わずに機械的に点検しています。

### NotebookLM を使うとき
資料が多いときは、先に NotebookLM で要点を整理させます。

1. NotebookLM に資料を入れる
2. 「指示文」→ **NotebookLM 用の要点整理** をコピーして、NotebookLM の質問欄に貼る
3. 返ってきた箇条書きを、**資料からの追加** の指示文と一緒に Gemini に貼る

### Gemini の返答がおかしいとき
- 囲み記号（```json）や前後の説明文は自動で外します
- 形式の誤りがある操作は自動で「却下」になり、理由が日本語で出ます。正しい操作だけ適用できます
- 「修正依頼文をコピー」を押して Gemini に貼ると、直した差分を出し直させられます

### 間違えたとき
上部の「取り消し」で1段ずつ戻せます（案件ごとに直近 20 段）。「履歴」からまとめて戻すこともできます。再読み込みやロックをすると戻せなくなります。

## データの扱い

- 台帳は**合言葉で暗号化して**ブラウザの中（localStorage）に保存します。開くたびに合言葉を入れます。合言葉と鍵はどこにも保存しません
- 合言葉を忘れるとブラウザ内の台帳は開けません。書き出したファイルからは戻せます
- 離席するときは上部の「ロック」で、台帳と鍵をメモリから消せます
- **ブラウザの保存は、閲覧履歴の削除などで消えることがあります。** 区切りごとに上部の「書き出し」で JSON を保存してください
- 書き出したファイルには案件の情報（関係者の氏名を含む）が入ります。社内の決められた場所に保存し、社外へ持ち出さないでください
- 書き出したファイルは「設定」→「台帳ファイルを読み込む」で開けます

## 開発（自宅PC）

依存パッケージはありません。Node.js だけで動きます。

```bash
node build.mjs                  # src/ から index.html を作る
node --test "test/*.test.mjs"   # テスト
python -m http.server 8765      # ブラウザで確かめるとき
```

- `src/core/` は DOM に触れない処理（検証・差分・健康診断・指示文）。テストはここを対象にします
- `src/ui/` は画面
- `samples/` はダミーデータだけです。**実案件のデータを置かないでください**（`.gitignore` で書き出しファイル名を除外しています）
- 仕様は `.claude/specs/workbench-p1/`
